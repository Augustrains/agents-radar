### 3. 共同关注的功能方向

各工具社区普遍在以下几个方面提出强烈需求：

1.  **自定义与多元化模型提供商（BYOK/自定义模型）**：
    *   **工具**：**Claude Code** (社区强烈要求BYOK), **OpenAI Codex** (#10867), **GitHub Copilot CLI** (#4016, #4139), **Kimi Code CLI**, **Pi** (支持Telnyx, Bedrock等), **Qwen Code** (#6996), **DeepSeek TUI (CodeWhale)** (#1481)。
    *   **诉求**：用户不满足于绑定单一大模型，要求能灵活接入自家、开源或性价比更高的第三方模型，以应对成本、隐私、特定场景任务等需求。

2.  **数据安全与操作稳健性（防误操作、防卡死、防数据丢失）**：
    *   **工具**：**Claude Code** (#78273, #75490), **OpenAI Codex** (#32997), **Gemini CLI** (#21409), **GitHub Copilot CLI** (#4097, #4138), **Pi** (#6716, #6715), **Qwen Code** (#7034)。
    *   **诉求**：用户对工具“自作主张”执行破坏性操作、无故卡死、内存泄漏、无确认覆写文件等问题零容忍。**“可控”** 成为超越“智能”的首要考量。

3.  **多智能体/子代理能力与可靠性**：
    *   **工具**：**Claude Code** (重构`/subtask`), **Gemini CLI** (#22323, #21409, #21968), **OpenCode** (子代理稳定), **Qwen Code** (#7034, #7048), **DeepSeek TUI (CodeWhale)** (#4010, #3205)。
    *   **诉求**：用户期望更复杂的任务分解和协作，但当前子代理在错误报告、状态同步、任务挂起等方面bug频发，严重影响可用性和信任度。

### 5. 社区热度与成熟度

*   **社区极活跃、功能迭代快速**：**OpenCode**, **Pi**, **Qwen Code**, **DeepSeek TUI (CodeWhale)**。这些项目Issues/PR数量多，讨论深入，团队响应积极，常处于快速迭代中，但稳定性问题也相应更多。
*   **社区成熟、聚焦高价值问题**：**Claude Code**, **Gemini CLI**。社区规模大，反馈的问题集中于成本、隐私、安全、稳定性等核心维度，反映出用户对工具的深度使用和成熟期望。
*   **社区活跃、痛点集中**：**OpenAI Codex**, **GitHub Copilot CLI**。社区活跃，但痛点高度集中（Windows卡死、会话卡死），已成为影响用户体验的“天花板”问题。
*   **社区规模较小，处于早期阶段**：**Kimi Code CLI**。功能迭代稳健，社区反馈倾向于基础的安装引导和小范围优化，尚未面对大规模用户带来的复杂问题。

### 6. 值得关注的趋势信号

1.  **“安全与可控”成为用户第一要义**：数据丢失、无权限操作、内存泄漏、任务卡死……这些关键词的高频出现，标志着AI编程工具已度过“好奇期”，进入“信任期”。开发者不再是尝试新玩具，而是将其作为生产工具。**承诺并实现零信任、零事故的安全基线**，将超出功能本身，成为赢得市场的关键决胜点。

2.  **“多Agent”从炫技走向实用**：无论是Claude Code的`/subtask`、OpenCode的子代理、还是CodeWhale的WhaleFlow，社区对多Agent的关注点已不再是“能否实现”，而是 **“能否可靠完成”** （如子代理错误报告、状态同步、成本控制）。这预示着多Agent能力将从实验性功能快速下沉为产品护城河。

3.  **MCP (Model Context Protocol) 生态是下一个战场**：OpenAI Codex、GitHub Copilot CLI、OpenCode等都在积极拥抱MCP。MCP作为AI与外部工具、数据源交互的标准化协议，其生态完善度将决定一个AI CLI平台能否成为**真正的“开发者中枢”**，而非又一个对话入口。

4.  **成本透明与管控成为刚需**：从Claude Code的“思考Token翻倍”到Gemini CLI的“自动记忆无限重试”，隐形成本的增加正成为新的痛点。用户不仅关注计费模式，更要求工具提供清晰的**Token消耗明细、成本归属（如项目/团队标签）、以及可配置的预算限制**。

5.  **平台化为王，独特性赋能**：OpenAI Codex、OpenCode、Pi等都在向开发者平台演进，提供插件、技能、自定义模型支持。这印证了 **“一个AI工具的上限，不仅由其自身模型决定，更由它连接的外部世界决定”** 的未来趋势。核心能力的差异化（如Claude Code的深度代理、CodeWhale的编排能力）则是最终吸引开发者留存的“钉子和锤子”。

## 开发者关注点

1. **“代理鸿沟”问题加剧**：开发者普遍反馈 Agent 在长对话或复杂任务中，时常出现**忽略或覆盖用户明确指令**的情况，尤其在低风险但关键的操作上。这导致了严重的不安全感，开发者需要的是“可控的工具”，而非“有自己想法的助手”。
2. **数据安全与不可逆操作是最大痛点**：当前最尖锐的反馈集中在 **无确认的文件覆写** 和 **worktree 机制引发的数据丢失**。开发者认为，AI 编程工具在获得充分的信任前，必须通过“确认→再确认”的机制来避免任何自动化的破坏性操作。
3. **“成本无预警激增”引发恐慌**：用户通过基准测试发现，仅仅升级 CLI 版本就导致 Token 消耗翻倍（#78320）。这种**隐形成本增加**（特别是 Thinking Token）比显式的定价变动更令开发者不安，他们需要版本升级带来的透明、可预测的成本变化。
4. **基础功能回归影响工作流**：新版本引入的 `/fork` 重构虽然意图良好，但导致了 **Sub-agent TUI 行为异常** 等回归问题。社区希望新版本在提供新能力的同时，不要破坏已经完善的基础功能（如终端兼容性、布局稳定性）。
