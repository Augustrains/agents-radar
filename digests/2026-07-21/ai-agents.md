## 3. 项目进展
过去24小时内，项目合并/关闭了112个 PR，主要推进了以下方向的修复与改进：
- **会话与状态管理**：修复了因 `cacheRead` 计入上下文总用量导致会话误判超限并触发压缩失败的问题（#108238），以及通过改进会话身份标识（run-handle identity）优化了“卡死会话”的恢复机制，避免误终止已完成的运行（#111622）。
- **工具与集成修复**：修复了 `MCP` 服务器配置中 `disabled` 标志被忽略的问题（#108676），并解决了 `browser` 工具在启用代理时快照失败的问题（#106482）。
- **前端与用户体验**：合并了针对控制 UI 媒体设置（#111971）和主题下拉菜单可读性（#111998）的改进，提升了用户界面的易用性和一致性。
- **信道适配**：修复了 Nostr 信道在正常关闭时误报中继错误的问题（#111905），以及 Zalo 信道未正确清理出站工具追踪信息的问题（#101431）。

## 4. 社区热点
讨论最集中的 Issue 反映了社区对**会话上下文可靠性**和**安全机制**的持续关注：
- **[#99241] Tool outputs sometimes render as image attachments and become unreadable to the agent (P1):** 此问题以23条评论成为今日最热的讨论。用户指出，在长时间运行的 ANSI 工具工作流中，工具输出会变成对 Agent 不可读的“图片附件”，导致 Agent 无法获取关键的 stdout/stderr 文本。这暴露了在处理富文本输出时的感知瓶颈，是影响 Agent 自主决策能力的核心问题。
- **[#88312] [Bug]: Codex app-server turn-completion stall returns (P1):** 22条评论，高达5个👍。这是一个 P1 级别的回归问题，报告了在 Codex 后端下，多工具 Agent 回合可靠地失败。它反映了核心推理链路的稳定性挑战，是开发者最为关切的“致命 Bug”之一。

## 5. Bug 与稳定性
过去24小时报告的 Bug 主要集中在**会话状态丢失**、**消息丢失**和**回归问题**上。

**高危 (P1，影响核心链路)**
- **[#87744] Codex-backed Telegram turns repeatedly time out (P1):** 更新后，Telegram 会话在使用 Codex 后端时反复超时，导致消息无法送达。暂无 fix PR。
- **[#92076] Subagent completion delivery can fail (P1):** 当请求者会话处于非活动状态时，子代理的完成结果可能无法送达用户。暂无 fix PR。
- **[#78562] Repeated tool-loop context overflows cause successive auto-compactions (P1):** 工具密集型会话进入重复的自动压缩循环，导致体验中断。此问题已在 v2026.5.5 中出现，至今未解。
- **[#102006] exec tool: aborted run wedges subsequent exec calls (P1):** 这是由 PR #94412 引入的回归问题。当 `exec` 工具运行被中止后，会话中后续的所有 `exec` 调用都会挂起。暂无 fix PR。
- **[#108238] 会话上下文用量误判导致压缩失败 (P1):** 近期版本（2026.7.1）的 Bug，导致了虚假的上下文超限告警。已被修复并关闭。

**中危 (P2，影响特定场景)**
- **[#101349] Agent-created crons inherit session toolsAllow at create-time (P1/P2):** 代理创建的定时任务会继承创建时的 `toolsAllow` 列表，且后续即使显式置空也无法清除，导致配置僵化。暂无 fix PR。
